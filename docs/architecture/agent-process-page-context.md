# 流程配置页面的受控对象与版本

## 范围

复用既有 `GET /api/approval-config/processes/{id}` 与流程领域服务，新增前端类型化详情调用，
将流程页选中对象、编辑版本、三个既有 Agent 写回执接入共享上下文与结果导航。
没有新工具、公共执行接口、迁移、写开关或任意 HTTP 能力；工具总数仍为 136。

`approval.process.createDraft/updateDraft/publishDraft` 仅从已成功任务的实际回执 `processId`
生成固定 `/oa/process-config?id=<正安全整数>`，先检查当前导航权限。不读取查询首行、模型参数或输出 URL。
页面再调用受保护详情核验返回 ID；后端继续实时检查 `approval:read`、流程租户和未删除状态。

## 页面与设计器

页面读取要求实时页面权限和 `approval:read`，维护再与实时 `approval:manage` 及行 `canEdit/canDelete` 取交集。
只发布已选实际 `processId/version` 和已应用 `keyword/status/page/size`；不发送流程节点、表单定义、
说明、名称、身份或设计器未提交内容。服务端页面白名单重新过滤，提示不能替代 Gateway 或领域授权。

类型化客户端、详情、列表、选项和设计器共用现有请求、安全错误和路由封装。
输入中的搜索文字不立即进入上下文；状态与分页变化触发实际列表请求，不沿用旧闭包筛选。
编辑前重新读取受保护详情与表单选项，用实际版本写入；关联表单不在首个选项页时，
仅用受保护详情的实际关联名称补充显示，不伪造表单记录。

设计器只生成领域命令，持久化由页面所有者统一执行，不在子组件独立处理成功回执。
保存失败保留输入和预期版本，成功定位实际结果并重读新版本。
用户/租户/权限变化、切换、关闭与卸载使旧读写序号失效，迟到响应不恢复旧选择或成功提示。
关闭输入验证中的设计器不继续发送保存；已发出的业务请求不被假装取消。
人工删除仍走原受保护接口与确认，不增加 Agent 删除能力。

## 关联名称隔离修正

反向测试复现：本租户流程意外引用另租户表单时，详情和列表会返回该表单名称。
`formNameOf/formNames` 在既有 ID 查询后补充同租户和未删除过滤，异常关联不输出名称；
正常同租户关联保持原名称。不改变流程/表单存储结构、关联关系或写入策略。
这些既有关联查询仍按 ID 读取后过滤，不把本节点说成所有数据访问层均已改为 SQL 级租户条件。

本节点验证：OA 定向 37 项通过，完整 52 个文件 370 项通过；lint 零错误、3 条既有警告，
TypeScript 与 Vite 生产构建通过。Java 17 `mvn clean test` 共 1355 项，零失败、零错误，
10 项既有环境依赖测试跳过。另显式执行 `P1PostgresMigrationIT` 零失败、零跳过，覆盖
真实 PostgreSQL 关联隔离、空库与旧库升级、157 项 Flyway validate、再次迁移零变更。
独立只读审查无阻断问题；保留既有组件弃用、大分包与聊天输入器样式提示。

组件覆盖实际选中对象、非法/错号、筛选、实时撤权、关闭和乱序、受保护编辑版本、
失败保留输入、写后新版本、迟到选项/写入与重复点击；共享导航覆盖三个回执。
关联名称先以领域单元测试复现，再以真实 PostgreSQL 随机迁移 Schema 的实际 Mapper 验证
异租户、同租户、删除关联及流程越权，访问解析采用测试替身，不等同真实 JWT/模型/Worker 端到端。

回滚同步回退页面、设计器提交契约、上下文白名单与回执映射；旧受保护详情接口不需删除。
关联名称隔离修正应独立保留或由等价保护替换，不因页面回滚恢复泄漏。
无迁移，不需要数据库回退；未开启写开关，也未完成全页面真实模型与浏览器验收。
