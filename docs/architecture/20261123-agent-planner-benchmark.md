# Agent 规划超时与日期追问基准

测试日期：2026-11-23（Asia/Shanghai）。

## 范围与方法

使用本地服务端 `.env` 中的真实模型配置，经过 Spring AI、`ChatClientPlannerModelClient`、`StructuredAgentPlanner` 的流式规划链路。每个场景顺序执行 3 次，修复前后共 18 次请求；不执行工具，不提交请假，不写业务数据库。凭证、完整模型输出和个人数据不进入报告。

这是环境变量配置的模型微基准，不代表已验证运行中服务的数据库在线 AI 配置，也不包含浏览器、HTTP、JWT、数据库和 Tool Gateway 的端到端耗时。扩展工具组包含 41 个通过公开定义方法构建的真实工具定义，用于候选目录压力对照，不代表某个用户的实际授权工具全集。

正确计划要求：不再追问、仅一个 `leave.apply` 步骤、起止日期均为测试时上海日期的次日。首段时间指前端可展示的首个非空 summary，而非网络首字节。

## 可重复故障与修复

1. 规划提示词没有可靠的当前日期。现在在系统提示中提供上海业务日期和时区，明确相对日期解析规则；不会从用户页面上下文读取可信日期。
2. 原线程池 core=1、max=2、queue=8，队列未满时第二个请求不会启动第二个线程，排队时间会消耗 `Future.get(15000ms)` 的预算。回归测试用两个同时占用的请求验证：旧配置在 2 秒观察窗口内无法同时启动，新配置通过。现在 core=max=2、queue=0，超过容量立即返回不可用，不隐式排队。
3. 原来模型超时后重复请求一次，典型超时等待约 30 秒。现在超时、执行失败、取消或容量不足均不自动重试；只保留一次结构化候选格式错误重试。100ms 可控延迟测试验证只发起一次调用，修复后测得约 104ms 返回。
4. 保留 15 秒规划上限、工具权限和确认机制。补充低敏日志：尝试次数、排队时间、总耗时、候选工具数量和是否追问；不记录提示词和密钥。
