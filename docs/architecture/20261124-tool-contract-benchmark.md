# 工具说明、选择和耗时验证（2026-11-24）

## 本次改动

- 模型收到的已授权工具增加名称、完整描述、适用/禁止场景、原始输入 Schema、两层深度的精简返回结构、副作用和确认要求。
- 共享参数说明只发送一份；五个常用工具提供合成调用/返回示例，禁止复制示例编号、日期、版本和事由。
- 完善请假原子申请、草稿创建/修改、已有草稿提交、本人申请查询、审批待办、通知、同意/驳回的差异。所有候选都由既有 Registry 决定，模型自主选择；没有新增按用户关键词筛选工具的逻辑。
- 只追问真正缺失的必填业务信息，不因可选审批人、筛选、分页或审批意见多问。
- 不增加模型调用轮次，不把真实工具结果重新交给 Planner，不增加结果总结模型。执行仍经过持久计划、确认、Worker、Tool Gateway 和领域服务校验。
- 使用当前默认模型的实际上下文预算。过大时依次省略合成示例、共享参数注释、返回摘要及重复文案，保留全部候选、输入约束、用户上下文、副作用和确认规则；仍无法容纳则在模型调用前明确拒绝，不偷偷删除候选工具。
- 不修改执行 Schema、哈希算法、权限范围、写工具启用状态、15 秒规划上限或 Flyway 迁移。

## 静态契约和文档开销

扫描并验证 163 个代码注册工具契约。文档字段覆盖与所有合成示例通过对应的真实输入/输出 Schema 校验；展示层未改写源 Schema。

对这 163 个契约进行 10 次预热和 50 次文档生成与序列化测量：中位数 1ms，p95 2ms。全量文档约165615字节，该数值用于开销测试，不意味着每个用户每次都会发送163个工具；实际列表由页面、权限与工具策略过滤。预算适配测试覆盖 16384 上下文/4096 输出上限的合法小模型配置，并经过实际 `AiProviderRuntime.prepare()` 校验；不可容纳的输入在模型调用前失败关闭。

## 真实模型测试

全部使用服务端环境变量配置和合成输入，没有执行业务工具或提交申请。最终验证经过实际 `AiConfig`、`AiProviderRuntime.prepare()`、模型客户端、规划器、Schema 校验链路；配置 Mapper 和用量记录使用测试替身，没有读取或修改在线 AI 配置库。它不能替代真实数据库和 Tool Gateway 的端到端性能测试。

主用例共九类，每类两次：申请请假、只存草稿、提交已有草稿、本人申请查询、审批待办、系统通知、同意审批、驳回审批、明确缺理由。检查单一步骤、工具名、必需参数、日期和半天、原文理由/意见；最终版对查询额外检查不得凭空增加记录编号和筛选条件（允许服务端明确的分页及待办默认值）。
