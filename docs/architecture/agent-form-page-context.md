# 表单管理的受控对象与设计器闭环

## 范围与复用

复用既有受认证 `GET /api/approval-config/forms/{id}` 和表单领域写入接口，补充前端类型化详情客户端。
服务端仍实时检查 `approval:read`、所属租户、删除状态；维护另需 `approval:manage`。
三个既有 `approval.form.createDraft/updateDraft/publishDraft` 的成功回执仅取实际 `formId`，
经最新导航权限过滤后定位固定 `/oa/form-engine?id=<正安全整数>`，不从查询首行或模型参数推断对象。

决策：表单与流程具有相同的对象、版本、筛选和设计器生命周期，将既有流程实现抽为
`useApprovalDefinitionPage`，由两个真实页面复用；保留不同设计器和领域命令，不抽象任意页面/HTTP 调用。
该 Hook 管理受保护读取、实际版本、写后重读、生命周期和人工删除确认，不承担服务端授权或状态机。
流程的可选表单选项仍只在打开设计器时读取，不扩大列表或 Agent 上下文数据。

## 对象与版本

默认不选第一行，只发布实际选中的 `formId/version` 和已应用的 `keyword/status/page/size`。
新建时不继承旧对象；输入中的搜索文字、设计器字段、名称、说明及整个 Schema 不进入上下文。
后端按页面字段白名单再次过滤，客户端上下文不授予权限。
编辑先重读实际详情与版本，写入用新版本；失败保留输入，成功按实际返回 ID 重读详情。
页面/业务实时权限与行操作标志取交集，不按旧角色或旧行标志显示维护入口。
切换、关闭、卸载和权限变化使旧请求失效；已发出的写入不假装取消，迟到回执不恢复旧对象。
人工删除保留原领域接口并重新校验确认作用域，不新增 Agent 删除能力。

## 字段持久化修正

失败测试复现原设计器保存输出 `fields[].key`，但领域发布校验和动态表单按 `fields[].name` 读取。
保存时将设计器内部 `key` 转为 `name`，剔除内部随机 `id`；读取优先用规范 `name`，
兼容旧设计器实际生成的 `key`，避免将旧字段标识替换为默认 `text1`。
不批量修改历史 Schema、不迁移已有申请快照，不宣称旧申请数据自动修复。
设计器提交改为向页面所有者返回类型化命令，不再在子组件独立调用接口或处理迟到成功。

## 验证边界与回滚

本节点实际验证：表单组件 19 项、流程组件 17 项、详情客户端 5 项和共享导航 17 项通过；
OA 全量 53 个文件 391 项通过，lint 零错误（3 条既有警告），TypeScript/Vite 生产构建通过。
Java 17 `mvn clean test` 共 1356 项零失败、零错误（10 项既有环境依赖跳过）；
其中页面上下文过滤定向 12 项通过。独立只读审查无阻断问题。
本节点没有数据库结构、种子或领域持久化变更，不重复数据库迁移/重启门禁。
保留既有组件弃用、大分包及聊天输入器样式提示，不宣称这些旧提示已解决。

组件测试使用真实 Ant Design 页面、设计器、路由和上下文，替换认证与网络边界；
覆盖规范/历史字段标识、创建、发布、版本冲突、撤权、乱序、关闭和对象切换。
流程已有组件测试同时回归，覆盖共享抽取没有改变流程选项和写入行为；服务端过滤测试不接受 Schema/草稿身份。
这些不等同真实模型、Worker、浏览器响应式或所有页面逐项验收。

后续实质缺口：既有 `approval.configuration.query` 仅返回配置摘要，不返回字段定义；
本节点的详情 API 是受认证页面客户端，不会自动变成模型工具。
因此 Agent 根据自然语言在完整现有字段上做局部修改，仍需独立交付受控、类型化的字段详情读取工具，
并验证读取、单写确认、实际结果和浏览器定位，不能用把整个 Schema 塞进页面上下文代替。

本节点无新工具、迁移、依赖或写开关，工具仍为 136 个。单写步骤、人工确认、租户边界和永久禁止能力不变。
回滚需同步回退页面、设计器提交契约、共享 Hook、导航和上下文；不能仅删除 Hook 留下调用方。
字段标识修正应保留或用等价保护替换，避免恢复写入不可发布字段的缺陷；无数据库回退步骤。
