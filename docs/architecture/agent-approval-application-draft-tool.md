# 通用审批草稿 Agent 原子工具

## 能力边界

`approval.application.createDraft` 仅为当前认证用户保存一条 `DRAFT` 通用审批申请。它不启动流程、不创建待办、不发送审批通知，也不替用户作出审批决定。

工具输入使用封闭的 `formKey`、可选 `processKey` 和字段列表。租户、申请人、角色、权限及数据范围不允许由模型传入。动态表单值在 Adapter 中转换为页面接口使用的结构，随后仍由 `GenericApprovalService` 按实时表单 Schema 校验字段白名单、类型、选项、长度和总载荷。

## 复用与服务化

Handler 只解析冻结契约并生成稳定操作键；`ApprovalApplicationToolPort` 只包含 Java 值对象，不依赖 Spring、Jackson、HTTP、DTO、实体或 Mapper；本地 Adapter 调用与页面共用的 `GenericApprovalService`。未来拆分审批服务时替换 Adapter，并保留可信身份、固定服务目标、远端重复鉴权和稳定操作键核验协议。

同一租户、申请人和操作键由数据库唯一索引约束。完全相同的重放返回原草稿；表单、流程、字段或状态不同均返回幂等冲突。申请与业务审计处于同一事务。

## 安全与发布

- ToolGateway 同时检查业务权限 `approval:create` 与独立工具权限 `agent:tool:approval.application.createDraft`。
- 领域层再次检查有效用户、租户、`route:approval-start` 与 `approval:create`。
- 风险等级 L1，显式确认，单写步骤，业务幂等。
- 全局和租户写开关继续默认关闭，开发完成不代表生产发布。
- 禁止通过此工具提交、撤回、审批、批量创建或修改流程配置。

## 取消草稿的领域事务前置修复（2026-10-22）

核对费用取消工具前置条件时发现，通用取消草稿虽然按租户、申请人、DRAFT 和版本条件更新，
成功审计却调用 REQUIRES_NEW 的 record。真实 PostgreSQL 回归证明：外层事务在审计之后失败时，
申请状态/版本/完成时间回滚，但取消成功审计仍留下了一条。

取消成功审计现改为 recordTransactional，与既有取消状态迁移共用领域事务。
普通取消和既有通用 Agent 取消入口复用同一个修复；权限、状态条件、版本及拒绝审计没有改变。
审计写入失败向外传播，不返回伪成功；外层后续失败时，取消与成功审计一并回滚。
不修改、删除或自动修补历史审计，避免从不完整历史推断实际业务结果。

真实库回归给审计服务安装实际 Spring 事务拦截器，外层使用 TransactionTemplate 表达已有领域事务，
不再用无代理的手工实例冒充事务传播验证。覆盖审计失败、成功审计后外层回滚、正常提交、
重复取消及并发取消；同版本并发仅一次生效、一条成功审计、版本仅增加一次。

无数据库结构/迁移、工具 Schema、权限种子或写开关变化；费用专属取消工具尚未接入，
仍需在后续节点交付，不以此修复替代工具注册、发布门或真实 Agent 验收。
回滚会重新引入虚假成功审计风险，应先停用相关取消写入口；不应删除已有业务数据或历史迁移。

验证：通用审批 31 项定向测试通过；完整后端 mvn test 为 1325 项零失败、零错误，
10 项环境依赖测试跳过。显式 P1PostgresMigrationIT 1 项多场景集成测试零失败、零跳过，
空库应用 154 个迁移、155 项 validate、旧库升级和重新创建 Flyway 实例后零迁移通过。
测试仅使用随机隔离 schema，运行后自动清理，未升级或改动开发库业务 schema。
OA lint 零错误（3 条既有警告）、298 项测试及 build 通过，保留既有组件/样式及分包提示。
未执行真实模型、Worker 或全页面浏览器验收，也未重启用户正在使用的应用进程。
