# 会议室基础资料写入前置条件

## 范围与接口

本里程碑修复现有会议室资料编辑的并发与审计边界，为后续类型化 Agent 工具复用领域服务准备基础，**尚未新增会议室资料编辑工具**。
预约与取消继续使用既有 `meeting.book` / `meeting.cancel`。工具登记数量保持不变，禁止删除、单写上限与人工发布门不变。

- 列表、详情、创建、更新的会议室响应增加 `version`，创建固定为 0。
- 既有更新接口的请求必须携带读取时的非负 `version`；缺少版本返回 `VERSION_CONFLICT`，负数也会被请求参数校验拒绝。
- 更新条件同时包含会议室 ID、认证租户、未删除和请求版本，成功后版本加一；旧版本或并发败方不会写入。
- OA 编辑弹窗携带打开时的记录版本，而不是自动读取新版本重放旧修改；请求失败保留弹窗及输入，不显示成功。
- 创建和修改的业务审计与资料变更处于同一事务，审计失败回滚；不修改已有删除接口或开放 Agent 删除。
- 修改共用预约服务的会议室行锁，先锁定当前租户的会议室，再检查有效预约，避免关停检查与新增预约竞态。

## 迁移与部署

新增 `V202610201200__meeting_room_optimistic_version.sql`，仅增加非空整数列及默认值，不修改历史迁移。
旧记录升级后版本为 0，其他资料保持不变。部署应先执行迁移，再同步部署后端与 OA；重新打开的编辑页读取新版本。
旧浏览器或旧客户端缺少版本的编辑请求将被拒绝，不保留无条件覆盖的兼容路径。

回滚时停止新版本编辑流量并成对回退应用版本，保留版本列和 Flyway 历史，禁止删除历史或修改 checksum。
旧应用不具备并发覆盖保护，不应以应用回退作为长期运行方案；不自动重试结果未知的写操作。

## 验证要求与后续

真实 PostgreSQL 回归验证创建初始版本、版本递增、旧/缺失/负版本拒绝、两个并发修改仅一个成功、
审计失败的创建与更新回滚、有效预约阻止关停、跨租户和权限撤销拒绝，以及旧资料升级后默认版本为 0。
OA 交互测试验证发送记录版本和失败保留输入。完整前后端检查及 Flyway/开发库重启结果在交付清单记录。

后续仍需会议室资料专属类型化查询与创建/编辑工具、封闭 Schema、独立权限、工具注册迁移、默认关闭写开关、
确认与真实模型/浏览器验收。既有 `meeting.query` 的冻结结果不随本次响应字段扩展而改变，不能把页面版本字段擅自塞进旧工具 Schema。
