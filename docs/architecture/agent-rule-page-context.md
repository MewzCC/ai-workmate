# 审批规则页面与 Agent 记录闭环

## 目标与范围

基线 `cb72b364`。审批规则已具备三个受控写工具，但页面未连接受保护详情、实际选中对象和版本，
工具成功后只跳模块首页。此节点接通页面，不新增工具、公共执行入口、依赖或写开关。
沿用全页面计划，不把本节点或 138 个工具计数等同于全平台可用。

## 接口与复用

客户端补齐 `GET /api/approval-config/rules/{id}`，使用既有受认证请求；后端接口与领域鉴权不变。
规则页与表单、流程共用 `useApprovalDefinitionPage`，复用列表、保护详情、最新编辑版本、作用域失效、
请求序号、写后刷新、关闭及人工删除确认。规则条件/动作编辑器仍产生既有领域 Payload。
编辑前重新读取实际详情，不使用列表版本；读取失败或记录错配时拒绝回退列表数据。

固定结果映射只接受三个成功写回执中的正安全整数 `ruleId`，并按最新菜单权限定位
`/oa/approval-rules?id=<id>`，不信任模型 URL、候选参数或查询列表首行。
Drawer 只读展示详情；不会因为定位就启用、编辑、删除或执行规则。
命中条件和动作使用只读 Ant Design 文本域展示服务端原始内容，保留未知属性和数值精度，不重新序列化或执行。

## 上下文与安全

页面只发布已应用的 keyword/status/page/size，以及明确选中且读取成功后的 ruleId/version。
服务端增加相同标量白名单；条件、动作、说明、编辑中未保存值、用户和租户标识均不进入页面上下文。
此上下文是不可信提示，不是授权，原 ToolGateway 与领域实时权限、租户、状态及版本校验不变。
当前页面和 approval:read 缺一时不读取数据；管理入口同时要求实时 approval:manage 与实际记录维护标志。
权限快照、用户/租户或记录选择变化使旧请求失效；关闭后迟到详情不能重新打开窗口。
失败保存保留输入和旧版本，只有真实写接口成功后才重新读取已保存版本。
界面人工删除沿用原服务端接口，Agent 删除能力仍永久禁止。

Ruling: 复用现有定义页生命周期而不再复制一套请求/权限逻辑——三页具有同样的选择与版本约束；
代价是共享 Hook 的改动需同时回归表单、流程和规则，设计器的领域语义仍由各页负责。

Ruling: 审查指出新建启用规则错误显示“更新成功”，按用户可见操作回归提升为必须修复；
共享 Hook 只在调用页显式提供发布文案时采用发布反馈，规则页按创建/更新选择文案。
代价是三页成功路径都须回归，不为单页增加通用发布模式或额外状态机。

## 未验收与回滚

不改变数据库结构、冻结工具契约或运行开关，不重复执行迁移或修改开发库业务数据。
真实模型、Worker、浏览器响应式、人工发布门仍待验收；本机 Redis 依赖此前连接失败尚未恢复验收。
规则详情 HTTP 客户端不等于 Agent 已能读取完整规则定义；后续自然语言局部编辑仍需类型化有界定义读取，
不能把整段条件/动作或编辑中内容直接塞入页面上下文，也不允许模型从查询结果递归生成写计划。
回滚同步撤回客户端详情、页面/共享类型扩展、白名单和结果映射，不回退已执行历史迁移。

后续受控定义读取已形成独立切片，见[规则定义读取工具](agent-rule-definition-read-tool.md)；
本页“尚需读取”的描述仅指页面节点当时的交付边界，局部写入仍需独立原子命令。
