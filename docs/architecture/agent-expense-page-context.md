# 费用报销页面的 Agent 上下文与记录定位

## 范围

费用已有 expense.query/createDraft/updateDraft/submitDraft/withdraw/reopen，
本节点接通页面的真实选中对象与结果定位，不新增工具，不开放写开关。
手工取消、催办仍调用既有普通审批 API，不因此新增 Agent 能力或扩大单写步骤上限。

## 页面与结果契约

- 复用 usePublishPageAgentContext，只发布当前申请 applicationId/version、
  实际状态筛选 status 及 page/size。没有选择不猜第一行，新建没有旧对象身份。
  金额、发票号码、事由、申请人身份、租户与未保存表单不进入页面提示。
- 服务端费用 Context Schema 增加数字 version，其他字段继续按白名单过滤。
  页面上下文只帮助 Planner 理解意图，不作为授权、乐观锁或确认凭据。
- 五个既有费用写工具仅从真实成功回执 applicationId 取得对象身份，
  先经过共享成功任务与实时导航核验，再进入固定 `/oa/expense?id=<正安全整数>`。
  expense.query 不取列表第一条，也不接受模型输出的任意 URL。
- 页面复用共享 ID 解析器及受保护通用申请详情 API，额外要求返回 ID 匹配、
  formKey 为 expense-application 且 applicantUserId 为当前认证用户；
  审批人/审计员能读取的其他申请不因此混入本人费用页面。
  这些浏览器校验不代替服务端认证、租户和资源授权。

## 生命周期与失败

列表、详情、编辑及认证范围有请求失效序号，身份/租户/权限版本变化时清除旧数据。
关闭、切换、卸载、读取失败及错号都不恢复旧选择，同 URL 读取失败可手工重试。
普通写入口匹配现有领域 API 的实时 route:approval-start 权限，并与服务端行标志、
本人及状态共同判断。Agent 仍额外受独立操作权限、ToolGateway、确认与人工发布门约束。

手工保存使用编辑时实际版本，失败保留输入。保存成功后即保留服务端新版本，
即使随后提交审批失败，也不能继续持有旧版本。表单关闭或权限变化发生在保存期间时，
不启动后续提交，也不假装取消已发出的事务；迟到结果不能覆盖另一条新选择。
状态确认在用户点击确认时检查原详情和认证范围是否仍有效，迟到结果不重开旧表单。
补齐重新编辑确认标题的 zh-CN/en-US 文案。

## 验证与回滚

组件回归覆盖最小上下文、正整数路由、ID/表单/本人匹配、关闭与乱序、撤权、新建、
按版本保存、部分成功后的新版本、晚到写响应与确认失效。服务端过滤测试覆盖隐私字段剔除；
共享导航回归覆盖五个回执和页面权限。

无数据库、迁移、冻结工具 Schema、Handler、Gateway 或写策略变更。
回滚需同步回退费用版本提示及记录映射/URL 读取，不撤销既有领域鉴权、事务、审计和乐观锁。
组件/契约测试不等于真实模型、Worker 或全页面浏览器验收；合同等页面仍须继续完成。
