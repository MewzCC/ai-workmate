# 工具描述、调用契约与选择质量完善

沿用用户已确认的五个环节：提供完整工具说明、区分相近操作、由模型自主选工具、仅追问缺失的必要信息、通过网关确认执行。

## 实现顺序

1. 在现有规划器上测九类真实模型请求，记录工具和参数正确性、模型调用次数、提示词字节数及耗时；不执行业务工具。
2. 先补失败测试：模型获得名称/描述/适用场景/输入与返回说明；示例满足真实 Schema；工具列表不增权、不按关键词过滤；规范化展示不修改 Schema 和哈希。
3. 新增仅用于规划提示词的工具文档投影。使用原始输入 Schema，返回值以固定深度的类型摘要表示。共享参数说明只发送一份，避免逐工具重复。常见易混淆操作提供精简调用与返回示例，示例只作格式说明，不提供真实资源身份。
4. 改善请假草稿、原子申请、已有草稿提交、申请查询、审批待办、审批同意/驳回的使用与禁止场景。其余全部已授权工具也获得现有名称、完整描述和输入/返回契约。
5. 同一组输入对比改动前后指标；跑规划器、工具契约、Gateway 安全与架构回归。若完整测试仍缺隔离数据库配置，分别记录可运行测试与环境限制。

## 范围与约束

不增加模型轮次，不改为关键词选择，不扩大 Registry 返回的工具集合，不直接注入或调用 Handler。保持最多一个写步骤、15 秒规划预算、受控重试和人工确认。只完善展示用文档，不修改已发布 Schema、哈希或 Flyway 迁移。执行结果继续由既有受控结果展示器返回，不额外调用模型总结，不将结果回传 Planner 循环执行。

真实模型基准使用服务端环境变量配置和合成数据，不能代替在线配置、真实数据库及 Gateway 端到端性能验收。扩展工具文档可能增大提示词，需要同时报告正确率和耗时，不能只报告其中一项。
