# Agent 工具契约安全工厂

## 目标

`ToolDefinitionFactory` 将 Phase 2 当前允许的工具收口为两种代码级安全配置：受控只读和单一原子写。所有工具仍显式声明业务权限、数据归属、风险、确认、重试和资源上限；工厂只固定不应由各业务重复选择的 Handler 版本、权限组合模式、副作用类型及审计级别。

`ClosedToolSchemas` 为单资源 ID 和“资源 ID + 乐观锁版本”等高频参数提供确定性封闭 Schema。属性名先经过代码白名单格式校验，生成结果始终包含 `additionalProperties=false`，身份、租户、权限和数据范围仍不得成为工具参数。

## 兼容与迁移

现有工具定义全部通过安全工厂创建，但输入输出 JSON 节点、Schema Hash、工具版本和运行策略保持不变。确定性片段只替换字节语义相同的既有 Schema，并由冻结 Hash 测试和 ToolGateway 契约门禁证明兼容。

未来迁移到 Spring Cloud 时，契约工厂仍属于 Agent 服务的代码所有边界；业务服务只接收类型化 Port 命令或固定内部协议，不共享数据库中的工具定义，也不能提高工厂确定的能力等级。

## 约束

- 数据库和租户配置只能关闭或收紧代码契约，不能新增工具或放宽风险。
- 只读工厂固定为 L0、无副作用、无确认和只读安全重试。
- 单写工厂固定为 `SINGLE_WRITE` 与完整写审计，风险、确认和重试必须逐工具显式提供。
- L2、禁止重试及二次确认等组合继续由 `ToolDefinition.validate()` 失败关闭。
- 不引入基于反射、注解、类名、Bean 名或数据库内容的动态工具装载。
