# 会议室原子预约工具

`meeting.book` 为当前认证用户创建一条会议预约，属于 L1、SINGLE_WRITE、BUSINESS_IDEMPOTENT、EXPLICIT 工具。不会替他人预约，也不提供删除、批量预约或外部消息能力。

## 分层与迁移

固定 Handler 经 `MeetingToolPort.book` 调用本地 Adapter，再进入 `MeetingBookingService.createAgent`。普通 OA 预约与 Agent 预约复用同一领域实现，不复制冲突检测、容量检查或审计逻辑。未来远程 Adapter 必须使用固定服务目标及可信服务身份，领域服务仍须实时鉴权，不能把客户端身份参数视为授权。

## 安全与一致性

- 工具执行唯一入口为进程内 Tool Gateway，执行前复核任务、租约、权限、确认与冻结契约。
- 需要 `meeting:book` 和 `agent:tool:meeting.book` 两层权限。
- 预约所属租户与组织者来自实时认证上下文，Schema 不接受身份或网络目标。
- 服务端以租户和会议室 ID 加锁，在同一事务中检查开放状态、容量、时间冲突，创建预约并写业务审计。
- 操作键由服务端 taskId、stepId、工具版本派生，不含 attempt；租户、本人、操作键有数据库唯一索引。
- 同一操作键重放返回原预约；不同内容复用操作键返回 IDEMPOTENCY_CONFLICT，不产生第二条预约。
- 输出仅含预约 ID、会议室 ID、状态、版本和时间，不返回组织者身份、议程或内部操作键。
- 全局与租户写工具默认关闭，代码完成不代表人工发布门已批准启用。

## 验证与回滚

定向测试覆盖冻结 Schema、网关身份映射、原子键、重复写入拒绝、停用用户与页面绑定。真实 PostgreSQL 门禁验证新列、唯一索引、种子契约及空库/旧库迁移。

`MeetingBookingPostgresVerifier` 在门禁创建的隔离迁移库中使用真实 Mapper 和 Spring 事务管理器，验证同键并发返回同一预约且只写一次审计、不同键重叠预约只成功一次、审计异常使预约整体回滚。幂等查询禁止 MyBatis 缓存并刷新会话缓存，避免加锁后再次读取旧的空结果。

回滚优先禁用单工具，保留已发布迁移及业务预约数据；不得修改历史 Flyway 文件或删除预约以模拟回滚。生产启用前仍需完成并发、结果未知恢复、权限回收及审计回滚的独立验收。
