# 员工档案的 Agent 对接与数据边界

## 页面操作核对

员工档案页的真实接口为组织列表、员工详情及档案附件列表、上传、下载。
当前页面没有独立的员工创建/资料编辑接口；不能为了工具数量新增账号创建或绕过入转调离的任职变更接口。
任职写操作继续使用 `employee-change` 页已有 `hr.change.apply/approve/reject/withdraw` 工具及领域流程。
这些工具仍受现有风险、写开关、确认、权限和单写步骤约束，不因档案页面核对而启用。

档案页已绑定 `hr.organization.query` 与 `hr.employee.query`，前者用于确定可见员工，
后者调用 `HrEmployeeToolPort` → 本地 Adapter → `HrService.employeeDetailForActor`，
重新解析实时 `hr:read`、租户及员工数据范围。未修改冻结 Schema、工具权限、版本哈希或登记数量。
不增加任意 URL、文件路径、数据库执行或模拟点击工具，不把员工附件读取等同于普通档案摘要。

## 当前选择与异步结果

页面只将最新组织接口可见员工中的当前选择作为 `employeeId` 上下文发布。
URL 仅提出选择意图，非法或不可见 ID 不触发该员工详情/附件请求；无可见员工时不发布 ID。
上下文不是授权依据，工具执行必须继续通过 Gateway 与领域数据范围校验。

列表、详情及附件请求分别有失效序号；结果绑定认证用户、租户、权限版本及选中员工。
切换员工、刷新、权限变化和卸载后，旧请求不得覆盖新结果；权限快照变化时重新读取组织列表，
旧员工详情与附件立即失去显示资格。上传完成后的列表重读只针对仍然选中的相同员工，
不将旧员工上传结果追加到另一个员工档案。

## 摘要与附件安全

已授权员工查询的文本摘要提供真实姓名、在岗状态、部门、岗位、直属审批人及六项考勤数值，
最多显示三条返回的任职历史，近期申请详情仍保留于结构化结果。摘要最长 1000 字符，
用户文本复用安全纯文本格式化，不输出联系邮箱、附件下载地址、文件内容或任职原因。
历史摘要受长度预算限制，不承诺文本包含全部结构化字段或全部历史记录。

普通档案附件接口新增实时数据范围复核：

- 本人附件自助读取保留；读取他人需要 `hr:read` 且目标在实时可见员工范围内。
- 上传需要 `hr:manage`；非本人目标也必须位于实时可见范围内。
- 文件下载在读取附件元数据和对象存储之前复核，不能持有旧下载地址后越过新数据策略。
- 数据策略异常失败关闭，不回退到同租户全部员工。跨租户认证与附件元数据租户条件继续生效。

这是有意收紧原有“只要 hr:read 即读取同租户任何档案附件”的行为；既有数据策略为 SELF 的人事用户
不能再读取或上传范围外员工的合同。需调整权限时由正式人工治理流程处理，Agent 不能修改权限。
普通页面上传/下载仍使用原受认证文件接口与安全上传策略；本节点不新增 Agent 文件工具或敏感导出。

## 验证与回滚

回归覆盖不可见 URL、当前员工上下文、附件请求乱序、实时权限变更、范围外读取/下载/上传拒绝、
策略异常关闭、本人自助读取及中英文真实结果摘要。普通上传对象键隔离、元数据失败与审计失败清理回归保留。
没有数据库迁移或工具启用操作。代码测试不替代真实模型、Worker、确认交互及全部页面浏览器验收。

回滚优先停止相关 Agent 任务并回退前端上下文与展示改动；不要回退附件数据范围检查以恢复越权行为。
本节点不变更业务数据、数据库结构或对象存储文件，无需删除迁移、清空档案或删除审计。
