# 费用草稿更新原子工具

`expense.updateDraft` 更新当前用户拥有的一条 `DRAFT` 费用申请。输入固定包含 `applicationId`、乐观锁 `version`，以及至少一个费用字段；模型不能指定表单、流程、租户、申请人、状态或提交动作。

工具采用补丁语义：费用领域门面读取本人固定 `expense-application` 草稿，将明确提供的字段合并到现有数据，再调用通用审批草稿更新事务。未提供字段会保留，避免一句“把金额改成 99.50”意外清空类别、日期、发票号或事由。通用审批层继续依据表单 Schema 校验合并后的完整数据，并以版本条件执行单次更新。

创建和更新 Handler 共用 `ExpenseDraftArguments` 有界参数解析器；更新 Handler 只补充资源 ID 与版本。领域状态机、实时鉴权、乐观锁和审计不进入 Handler，避免为每个页面复制安全逻辑。

安全约束：

- ToolGateway 校验任务快照、租户、用户、实时工具权限、确认、预算、租约、Schema 与参数哈希。
- 费用领域再次校验 `route:approval-start`、`approval:create`、同租户、本人归属和固定费用表单。
- 通用审批领域再次校验 `DRAFT` 状态、表单有效性、字段约束和乐观锁版本。
- 数据更新与 `DRAFT_UPDATE` 审计使用同一事务；审计失败时字段和版本整体回滚。
- 工具为 L1、本人范围、显式确认、禁止自动重试和单写步骤，写开关默认关闭。

未来迁移到 Spring Cloud 时，只替换 `FinanceToolPort` 的本地 Adapter。远程费用服务必须使用固定服务发现目标和服务身份，从可信调用上下文恢复用户与租户并再次鉴权；补丁合并、Schema 校验、版本更新和审计必须在费用服务单事务内完成，不能由 Agent 编排多个远程写步骤。

该工具不创建、不提交、不撤回、不审批、不付款、不上传或外发票据。
