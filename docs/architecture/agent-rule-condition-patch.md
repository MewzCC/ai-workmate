# 审批规则条件值局部修改

## 业务目标与分层

已有规则定义读取返回真实条件顺序，整份草稿更新工具仍需重传全部条件和动作。
为了支持用户只修改某个阈值，本切片先实现领域原子命令
`ApprovalEngineService.patchRuleDraftConditionAgent`，后续接入固定 ToolGateway 工具。
不新增 Controller、公共执行接口或自定义 JSON 路径，也不把读取结果交给模型自动循环改写。

本节点没有新增 Handler、Registry、工具权限、迁移或开关。工具目录仍为 139 个，
模型尚不能调用这条新命令；不能据此宣称规则局部修改或全页面端到端已验收。

## 命令与不变量

- 身份由可信调用方提供 `userId/expectedTenantId`，业务参数仅有规则 ID、版本、条件编号和值。
- `conditionNumber` 从 1 开始，对应真实定义读取的条件顺序；平铺定义只有第 1 个条件。
- 仅修改禁用规则，实时要求 `approval:manage`，重新核对可信租户；读取限定租户、ID、未删除。
- 请求版本范围 1 至 2147483646，条件编号范围 1 至 10；不存在的条件拒绝。
- 值为非空白文本，最多 120 字符；文本不修剪，不执行 Markdown、链接或表达式。
- 原值为数值时，接受 JSON 数字语法并用 BigDecimal 精确保存，小数 scale 限定为 -120 至 120；
  规范化后的实际值同样不得超过读取契约的 120 字符上限。原值为布尔时仅接受 `true/false`
  并保持布尔类型。文本型数字仍保持文本类型。
- 条件源和动作源沿用读取工具的封闭校验：各最多 64 KiB，拒绝重复属性、尾随内容、未知扩展和不支持的定义。
- 更新只写 `condition_json`、时间和递增版本；其他条件、组合逻辑、原值类型均保持，动作 JSON 不重写。
  名称、类型、优先级、说明和状态不受改动；不会因沿用高优先级数据而要求重写无关字段。
- 数据库更新重新限定租户、ID、未删除、禁用状态和版本；失败返回版本冲突，不写成功审计。
- `PATCH_CONDITION` 审计与修改在同一事务，摘要只含条件编号，不保存新旧条件值。

只返回真实的规则 ID、新版本、禁用状态、条件编号、字段、运算符和值七个属性，
不读取创建人，也不返回完整定义、说明或动作。读取与修改共用领域定义校验，避免两套规则分叉。
