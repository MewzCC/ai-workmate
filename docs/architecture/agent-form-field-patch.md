# 表单草稿字段局部修改交付记录

## 目标与边界

承接全页面 Agent 读写目标和 `agent-form-definition-read-tool.md` 的剩余项。
局部修改不能通过模型重建整份字段列表；必须是独立、单写、版本化的领域命令。
本节点先交付受控领域前置能力，后续固定 Handler/Port/Registry/权限种子接入同一命令；
不提供通用 JSON Patch、公开工具执行接口或模型指定的数据路径。

确定的输入：表单编号、版本、已有字段 name，以及可选 label、required、placeholder、width。
只能修改一个实际字段；不能改名、改类型、增删字段、排序、改变选项或数值约束。
null 表示未提供；空 placeholder 表示清空占位提示。空修改及无实际变化的请求拒绝。
未修改字段、历史 key、字段顺序、缺省属性与精确小数必须保持不变。
更完整的字段操作后续按独立语义命令交付，不以本节点替代全页面最终验收。

## 实施与验证计划

1. 先以真实领域调用和更新参数断言验证修改范围，观察缺少领域命令的 RED。
2. 新增内部类型化 DTO 和领域方法，复用既有封闭表单验证，不复制模板或状态机。
3. 实时检查 approval:manage 和可信租户，读取/更新 SQL 均限制 tenant/id/deleted；
   仅 DISABLED、最新版本可改，CAS 条件同时包含状态和版本，审计与修改同事务。
4. 真实 PostgreSQL 验证精度、租户隔离、版本冲突和审计失败整体回滚。
5. 完整运行前端 lint/test/build 与 Java 17 后端 clean test，独立中文提交。

Ruling: 将领域语义与新工具注册分为两个可验证节点——避免尚未证明约束保留时先授权新写工具；
代价是本节点不能由模型调用，不标记一句话修改已交付。既有写开关保持不变。
