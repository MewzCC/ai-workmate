# 浏览器可信来源与受控 Agent

本节点将允许携带 Cookie 的任意来源配置改成服务端精确白名单。白名单只决定浏览器跨来源访问，
不授予业务权限；JWT、实时数据库权限、任务所有权、租户及 ToolGateway 校验继续独立执行。
不增加 Agent 工具，不修改产品开关、写发布门或数据库迁移。

## 配置与请求顺序

`app.cors.allowed-origins` 从 `CORS_ALLOWED_ORIGINS` 读取，使用逗号分隔的 HTTP(S) Origin，
例如 `https://oa.example.invalid`。必须是协议、主机和可选端口，不允许路径、末尾斜杠、用户信息、
查询、片段、通配符或无效端口。非法条目使应用启动失败，异常不包含条目或 URI 解析原因，避免泄漏误填的凭据。
列表会去重；空值关闭跨来源访问，无 Origin 的非浏览器请求及真正同源请求仍按正常鉴权处理。

基础配置为空。仅 `dev` 配置默认允许 `localhost` 与 `127.0.0.1` 的 `3000` 和 `3001` 两个前端端口。
显式配置会替换默认值，设置为空可关闭开发默认白名单。生产、局域网和其他端口须显式设置精确外部来源。
反向代理必须保留真实 Origin，不得删除或改写成白名单值。代理改变 Host、协议或端口时，浏览器同源请求
在后端也可能被视作跨来源；应配置浏览器实际外部 Origin。不能根据请求 Host 或转发头自动扩大白名单。

CORS Filter 由 Spring Security 排在 JWT 前，禁用独立 Servlet 重复注册。合法预检无需 Cookie，
合法来源的 401/403 保留 CORS 响应头，使前端能处理真实错误；实际业务请求仍须认证。
不可信跨来源请求返回 HTTP 403、国际化 `Result` 错误，不反射来源或进入业务逻辑。
语言选择复用项目 `LocaleResolver`，支持多语言偏好协商；不支持的语言回退 `zh-CN`。
客户端现有请求方法、请求头、SSE 及追踪响应头保持兼容。

实现依据为项目 Spring Framework 6.1.14 的 [DefaultCorsProcessor 扩展接口](https://docs.spring.io/spring-framework/docs/6.1.14/javadoc-api/org/springframework/web/cors/DefaultCorsProcessor.html)
及 [Spring Security CORS 顺序要求](https://docs.spring.io/spring-security/reference/servlet/integrations/cors.html)。

## 验证边界

- 配置测试覆盖精确来源、空白名单、预检、现有客户端请求头、伪造子域/协议/端口、`null`、双语拒绝及非法配置。
- 安全切片覆盖合法来源仍需登录，以及带认证信息的不可信来源在规划前被拒绝。
- 真实 Cookie/HTTP 回归使用独立 PostgreSQL 数据库与专属 Redis 子进程，验证来源拒绝不改变任务或产生工具调用，
  合法来源仍受用户/租户隔离，且本人取消正常落库。原执行、SSE、权限撤销及状态机断言保留。
- 浏览器测试先选定独立回环 UI 端口，后端仅加入该精确 Origin；Vite 严格绑定该端口，冲突即失败，
  不回退其他端口，不修改生产白名单，不删除代理的 Origin。原模型读取、结果、跳页、持续对话和实际取消均须复验。
- 无 Origin 的服务调用仍由认证和领域权限保护；CORS 不能代替它们，也不声称阻止任意非浏览器客户端。
