# 侧边 AI 流式计划回复

`POST /api/ai/tasks/plan/stream` 接收与 `/plan` 相同的请求 DTO、JWT Cookie 和必填 `Idempotency-Key`，返回 `text/event-stream`。请求仍经过原计划服务的权限、租户、页面工具白名单、幂等、参数及预算校验；不会执行业务工具。

事件按实际进度推送：

| 事件 | 数据 | 客户端行为 |
| --- | --- | --- |
| `planning` | `status: PLANNING` | 显示等待反馈 |
| `reply` | `text`，当前完整的临时回复文本 | 更新生成中回复；重试时空字符串重置前次临时文本 |
| `plan` | `AiTaskPlanResponse` | 完整计划已通过服务端校验并持久化，替换临时文字 |
| `error` | `message/code/errorCode/status/requestId/traceId` | 展示失败，禁止将临时回复作为可执行计划 |

生产模型通过 Spring AI `stream().content()` 接收上游实际分片，不使用定时器模拟打字。只提取 JSON 顶层首字段 `summary` 的文字；半个转义字符等待后续分片，不向前端发送工具参数、原始 JSON 或提示词。完整 JSON 继续由原解析器校验。上游不按首字段约定生成时可能直到最终计划才出现完整回复。

流式规划使用独立有界线程池（2 个线程、8 个排队位置），避免占用工具执行池；保留每次模型调用时限和最多两次规划尝试。断连取消当前等待，不自动提交业务；工具执行仍走原确认及 Tool Gateway 链路。客户端断流后不会以临时文字构造计划，也不会自动重连重复规划。原 `/plan` 保留供既有调用方使用。

按用户要求，本次开发未运行自动测试。手动验收：输入请求后应立即出现等待提示，随后逐批显示文字；完成后临时提示消失并展示正式计划。校验模型失败、网络断连、中文输入法、回车发送、关闭后重开和页面切换。写操作必须继续确认，失败或半段回复不能执行。
