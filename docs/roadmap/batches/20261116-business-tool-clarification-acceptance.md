# 新增工具逐项缺参追问验收

基线 `301bec07`，目标为补齐 N1–N11 新增 11 个工具的缺参运行证据，不新增工具、权限或业务接口。

复用 `AgentLiveBusinessToolsIT` 的 14 个场景、数据准备、确认、网关、结果及重放断言。每个场景增加一轮缺少任务/员工/申请坐标的真实请求，要求返回不可执行的问句；只回复缺失的已核实坐标或理由，不重述全部请求，生成新任务与新哈希后执行原有真实业务断言。原追问不能申请确认、不能执行、不能调用 Handler，补充后必须关闭；写工具继续要求新计划的 L2 确认。

保留原完整参数 14 项作为回归，增加 14 项缺坐标、7 项缺必填理由和 2 项明确通过但意见包含负面内容的真实模型用例，共 37 项。理由场景覆盖通用/访客/用印驳回、转交、抄送、前后加签；输入有有效坐标但没有理由，不能让模型自行补写。仅使用合成身份和专属 PostgreSQL/Redis，不更改本地已启用配置或开发用户数据。外部模型仍需显式 `-EnableLiveModel -BusinessTools`，默认测试不外呼。

裁定：追加独立缺理由场景，因为 N2 计划明确要求缺理由时询问，不能由缺坐标场景间接代替；复用同一验证函数，不新增领域实现。

验证顺序：先运行显式真实模型，若发现行为缺陷则按证据修复；完成定向和必要完整门禁后独立中文提交。前端无修改时复用同一已验证子树，不重跑不相关页面。

本批实现和验收已完成，最终证据见下文。该矩阵证明固定场景，不声称穷举全部工具、参数组合、所有页面深层交互或生产发布。

## 已暴露问题及裁定

- 首轮 28 项中 5 项在完整回复后仍追问。移除初始缺坐标请求中沿用的“这些是已核实的任务坐标”矛盾语句，并增加理由专项后，35 项仍有 5 项失败；因此没有通过反复重跑将其计为通过。
- 第二轮模型明确问“第一个任务”和“第二个任务”，证明纯文本串接被误当成两项操作。新增 Planner 内部补充入口，将原请求、已保存问句、本次原文分字段提供；真实模型提示词升级为 `phase2a-v3-clarification-update`，明确补充属于同一请求、后续明确值补齐之前缺失值，所有字段仍是不可信数据。存储、累计预算、事务、幂等、原页面权限、确认及网关不变。
- 新增结构测试在旧实现上观察到缺少上述分字段边界而失败；再实现结构化入口。问句必须来自已锁定任务，非文本、空白或超过 500 字符拒绝；客户端不能指定问句。
- 随机标识单独作为理由被模型认为缺乏业务含义，夹具改为真实语义中文加随机验收标识。用户明确提供的自由文本仍应原样保存，不由模型自行补写或评判理由是否成立；最终业务权限和状态由领域校验。
- 一个场景包含受控候选读取加单写，是原有“最多一个写步骤”允许的计划，并非重复写。断言允许同一任务、同一协作用途的单个候选读取前置，仍禁止无关读取、多写或不匹配任务；逐步实际调用次数、唯一业务效果及重复执行继续严格核验。
- 结构化后，重述完整请求的 35 项已全过；进一步改为只回答缺失字段，暴露一次明确“通过”被模型改成“驳回”，以及理由标签被计入原文。补充系统规则要求动作取自明确请求，不由意见正负推断；新增访客/用印两项负面意见但明确通过的回归，普通场景使用中性业务说明。理由补充直接使用原文，不添加“理由：”标签，严格核对原值，不通过裁剪结果放松断言。
- Windows Node 24.15 驱动再次发生 `0xC0000409`，即使已使用 `--no-maglev`，没有 JS 或页面断言失败。后续改用隔离下载的官方 Node 22.23.2 驱动，先匹配官方 SHA256；不替换全局 Node、不修改应用依赖、不降低浏览器断言或增加自动重试。此前原生退出的浏览器用例不计为通过。
