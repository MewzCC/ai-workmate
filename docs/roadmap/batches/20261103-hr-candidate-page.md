## 改动

- 流程审批人使用受 `hr:manage` 保护的 `reviewer-options`，搜索和翻页复用 `BusinessUserSelect`。候选由服务端当前租户、有效用户及实际权限决定，不再从组织列表按 `SUPER_ADMIN` / `SYSTEM_ADMIN` 名称推断。
- 本人、权限版本和租户组成页面作用域。列表、详情及搜索条件按作用域展示；旧查询响应不得覆盖新列表或详情，旧员工搜索词不带入新身份的请求或输入框。列表请求失败清空当前记录，使用真实错误提示。
- 详情 URL 只接受合法正整数，并通过受保护的详情 API 查询。接口返回的业务 ID 必须与请求一致；后到的旧选择不得覆盖当前选择。
- 创建在校验前同步加锁，提交时禁用字段，校验失败留在表单内；关闭旧表单后重新填写的草稿不受旧写回调影响。完成后刷新最新筛选条件，而非提交开始时的列表状态。
- 审批、驳回和撤回同时检查实时页面权限与记录能力标志，仍传既有业务版本。提取仅管理本页确认框的 `useScopedModalConfirm`，撤权或卸载时销毁本页确认框，已捕获的旧确认函数不能在身份切回后恢复执行。
- Page UI 命令注册、表单填充、预览及工具发布门不在本批；相关工作区改动保留。现有只读页面上下文发布继续使用已提交模块。
