# 新增工具逐项真实模型验收

基于 `ce0aeaa2`，仅补验收资产与显式运行入口，不新增工具、业务接口或模型权限。默认 `mvn test` 不外呼模型，新用例继续使用 `IT` 后缀。

## 覆盖范围

`AgentLiveBusinessToolsIT` 同时向实际模型提供本轮 11 项有权限工具，使用自然中文请求选择工具、生成参数，再经真实 Cookie、HTTP、确认凭证、Worker、Tool Gateway 和领域事务执行，不冻结或伪造模型计划。

| 能力 | 场景数 |
| --- | --- |
| 通用审批驳回 | 1 |
| 访客通过、驳回 | 2 |
| 用印通过、驳回 | 2 |
| 通用审批转交、抄送 | 2 |
| 前加签、后加签 | 2 |
| 转交、抄送、加签人员候选 | 3 |
| 员工档案及用印留档元数据 | 2 |
| 合计 | 14 |

每例使用合成身份及专属 PostgreSQL/Redis 环境，正常业务数据随机生成；模型不能预知附件展示名。读取必须匹配实际记录，不能暴露私有存储键或表单内容。写入必须保留 L2 和二次确认，缺凭证返回 409、领域状态不变且 Handler 未调用；确认后实际执行成功，重放不产生第二次 Handler 调用。

结果同时验证真实业务状态：审批决定匹配申请/任务，协作和加签仍保持申请待审批，附件名称匹配数据库，候选包含符合资格的指定人员。工具选择、任务坐标、版本、理由、加签模式和候选用途都核对实际模型输出。

## 运行与证据

沿用现有服务端配置与私有验证环境，显式执行：

```powershell
./scripts/verify-agent-live-model.ps1 -EnableLiveModel -BusinessTools
```

数据库和原生 Redis 设置仍按原验收脚本要求通过本地测试环境提供。`-BusinessTools` 不能与 `-Browser` 或 `-LeaveWrite` 混用，且仍必须有 `-EnableLiveModel`；已验证两种无效调用均在读取模型配置、创建资源或调用模型前拒绝。脚本只输出工具代码和测试摘要，不打印凭据或模型业务正文。
