# N6 通用审批转交与抄送

基线 `c157a7a4`，对应[业务缺口计划](../20261109-missing-business-capabilities.md) N6。实现和自动化验收已完成；未推送或部署，运行启用及人工发布门另行验收。

## 范围与裁定

- 新增明确的转交、抄送、分页候选领域命令和认证接口。Controller 将认证用户及租户传入 Service，不接受模型或浏览器指定操作者和租户。
- 转交仅改变当前任务的受理人，不修改提交时冻结的 `approval_execution.plan_json`、规则或节点。后续办理从冻结原受理人起校验同任务的转交历史链，保留节点顺序、任务编号和到期时间。
- 转交接收人必须是同租户启用用户，并具备实时 `approval:act` 和 `todo:read`。抄送接收人必须是同租户启用且具备 `todo:read` 的用户；抄送只授予该流程的只读访问，不产生审批任务，不授予业务写权限。
- 候选在数据库完成资格过滤后真实分页，每页最多 50 条；仅返回展示字段和受保护的头像地址，工具结果不包含头像、邮箱或表单内容。不得先截取全局人员后在内存过滤。
- 所有协作写入与审批、撤回共用申请聚合锁顺序，重新读取任务并比较版本；协作成功后同时递增任务及申请版本，确保重复请求与并发请求只有确定胜者。
- 抄送去重按流程及接收人判断，同一接收人不重复发送。每个任务最多 32 次转交、32 次抄送，限制审计链和通知规模；超过时明确拒绝，不截断历史后继续办理。
- 记录操作者、原处理人、接收人、理由、时间和追踪号。业务审计、工作流日志和站内通知全部在领域事务内写入，失败整体回滚。不存在外部发送或角色权限变更。
- 转交返回独立回执，不尝试用原处理人的身份读取已转出的任务详情。前端转交完成后关闭旧详情；抄送完成后重新加载当前任务版本。通知详情通过真实受保护接口检查后进入固定通用任务路径。

## Agent 边界

新增 `approval.genericTask.participants.query`、`approval.genericTask.transfer`、`approval.genericTask.cc` 三个固定工具。只读候选工具明确接受任务及协作用途；写工具限定任务、明确接收人、任务版本和用户提供的理由。缺少信息必须追问，不能编造用户编号或理由。

两个写工具为 L2 / SECONDARY / NEVER / SINGLE_WRITE，继续受单写步骤、网关租约、实时权限、确认哈希、预算、审计和 Kill Switch 约束。三个工具通过新迁移 `V202611091400__generic_task_collaboration_tools.sql` 登记，均默认关闭。没有修改历史迁移或开启运行写能力。

## 接口与数据

- `GET /api/generic-approval-tasks/{taskId}/participants?purpose=TRANSFER|CC&keyword=…&page=1&size=20` 返回统一分页候选，先校验当前任务归属、实例、冻结节点和实时办理权限。
- `POST /api/generic-approval-tasks/{taskId}/transfer` 与 `/cc` 接受 `targetUserId`、`version`、`reason`。接收人是业务引用，不是操作者身份；租户和操作者只能来自认证上下文。
- 返回 `Result<GenericApprovalParticipantReceipt>`，包含申请 / 任务编号、任务及申请状态、任务版本、动作、原处理人、接收人和当前受理人。状态仍为 `PENDING`，不将协作结果解释为批准或拒绝。
- 详情增加服务端 `canTransfer` / `canCopy`，历史旧字段缺失时前端保持关闭。转交不创建新审批任务；抄送不改变原受理人。
- 非法参数、无权限、无资源及版本 / 状态冲突分别按已有国际化错误体系返回，错误不回退模拟成功。

## 部署与回滚

本批仅新增工具元数据迁移，不修改业务表或历史迁移。部署须保持前后端及工具合约版本匹配；新工具运行开关仍需独立人工发布门，不能因种子角色权限存在而直接开放。

回滚前先关闭新增工具并处理其未执行任务，保留工作流历史和已执行迁移。旧后端不再登记这三个工具，不能承担其重新规划或执行；历史任务应由支持该版本的服务读取。元数据需要补偿时新增迁移，禁止删除 Flyway 历史或改写校验和。前端回退会失去协作入口和通知详情跳转，不能声称完整功能仍然可用。
