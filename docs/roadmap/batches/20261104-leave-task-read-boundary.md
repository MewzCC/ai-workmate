# 请假任务读取边界与历史节点

批次 9G-1，承接 `6227b098`，只提交请假任务详情、时间线读取与请求节点投影的修复。审批管理前端、通用申请人工审批及其他积压文件分别处理；分支为 `feature/zcc`。

## 问题和修复

原详情与时间线只验证任务租户，随后把任务业务编号当作请假编号读取。其他业务类型存在同号记录时会错误返回请假；通用查询又优先选择当前待办，使读取历史节点时出现当前节点编号、版本及可审批状态。

新增固定 Mapper 查询，同时绑定任务编号和租户，并关联任务/流程的业务类型、业务编号、租户、申请人及人员所属租户；请假入口仅接受 `LEAVE_APPLICATION`。不合法编号返回参数错误，业务或关联不匹配返回资源不存在，无关用户返回无权访问。详情与时间线复用同一领域入口，保留申请人、当前/历史处理人、有效抄送关系和审计权限的合法读取。

详情返回实际请求节点的编号、版本、处理人、状态及催办时效字段。`canApprove` 同时要求申请和该节点待处理、本人处理人及实时审批权限；历史已关闭节点只读。写接口仍自行鉴权，不用前端布尔值代替检查。

保留现有 URL、`Result<T>`、JWT Cookie 与国际化错误码。没有数据库结构或迁移修改，没有新增 Agent 工具、发布开关或网关旁路。查询只读取必要人员展示字段。
