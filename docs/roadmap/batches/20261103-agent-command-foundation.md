# 原子申请与页面交互工具基础

积压批次 8B，依赖 `89384afa` 的原子领域事务及此前候选查询接口。此次收口工具注册、类型化 Port/Adapter、页面能力目录、真实回执、固定导航及执行门禁；各业务页面的浏览器处理器继续按业务拆分。

## 独立范围

| 工具 | 合约与边界 |
| --- | --- |
| `approval.application.apply` | 一个本人原子申请命令，L1 显式确认、禁止自动重试；复用同一领域事务，不串联创建草稿和提交两个工具 |
| `expense.apply` | 一个本人费用原子命令；金额、分类、日期、说明必填，返回实际申请编号、状态和版本 |
| `hr.change.reviewer.query` | 有限分页，只读同租户有效、具备实时人事管理权限且非申请人本人的候选 |
| `visitor.host.query` | 有限分页，只读同租户有效接待人的编号和姓名 |
| `page.ui.prepare` | 只准备固定导航、筛选、详情、未提交表单或刷新指令，不提交业务，不提供任意 URL、DOM、HTTP 或代码执行 |

所有 Handler 继续由 Tool Gateway 分派，不能由 Planner、Controller 或 Worker 直调。新写工具保持全局目录默认关闭，未开启发布门。普通页面只能准备自身指令；Workspace 仍要校验目标页面的实时权限。页面准备成功只说明服务端已返回受控指令，浏览器应用成功需要后续桥接验收，不能视作实际业务完成。

候选 Adapter 将预期租户传入领域查询，在解析当前用户权限后、SQL 查询前再次绑定；普通页面候选 API 保持原调用契约。表单准备只读取 `(tenantId, userId, taskId, RUNNING)` 条件下的任务页面与冻结上下文，不先按 ID 读取其他用户的任务。快照解析拒绝重复键、尾随 JSON、缺少会话的记录绑定和不完整版本。

通用和费用回执分别验证实际 `PENDING` 状态、编号、表单和版本，再输出双语提交结果，明确尚未审批通过。前端固定导航表增加对应业务入口；`page.ui.prepare` 不走普通业务结果自动跳转，避免把准备态误当成浏览器已应用。
