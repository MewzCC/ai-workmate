# 通用申请与费用原子领域事务

积压批次 8A，为后续原子工具注册提供已经验证的领域实现。此批收口 Service、类型化 Port/Adapter、表单数值读取与实际数据库检查；工具 Code/Handler、Schema/迁移、页面交互及发布开关继续按依赖归入后续批次。

## 事务与授权

- 通用申请在一个 Spring 事务中创建本人草稿、校验提交、冻结表单/流程/规则、建立流程和当前待办，写入创建与提交业务审计，返回实际申请编号、状态和版本。
- 费用申请复用同一事务，增加费用入口权限、金额、分类、日期及说明校验；不复制另一套审批引擎。
- 新领域入口接收从可信 ToolActorContext 传来的预期租户，重新解析用户当前租户与业务权限并比较；锁定当前租户的有效申请人，再执行本人的申请事务。浏览器和工具参数都不能选择认证身份或租户。
- 以现有 `(tenant, applicant, operationKey)` 作用域查找已有申请。锁定申请人让同键并发串行；相同有效请求返回同一份已提交回执，参数冲突拒绝，既有草稿不能被另一条创建命令偷换成提交。
- 幂等回读继续要求申请仍为 `PENDING`、版本 1，且当前表单/流程和请求一致。配置或状态变化时保守拒绝，不创建第二笔；此批没有承诺跨状态变化的自动结果恢复。
- Service 事务保持领域本地边界，Port 使用类型化命令和回执。未来远程 Adapter 仍须携带可信租户坐标并在远端重新鉴权，不以 RPC 或 Gateway 替代领域授权。

## A23 数值一致性修复

复核发现原有表单回读与 JSON 幂等比较采用默认浮点读取，且 `money` 未进入数值校验分支。此次修复：

- 创建草稿、编辑草稿和直接提交 DTO 的 `formData` 使用独立精确小数反序列化，后续流程字段仍正常读取。没有修改全局 ObjectMapper，也不改变冻结工具 Schema 的序列化或哈希协议。
- 数据库回读保留 BigDecimal；`number`、旧 `amount` 和 `money` 共用数值校验，使用精确十进制最小值比较，保留既有有限数值范围限制。
- JSON 幂等比较忽略对象字段顺序及数值的小数位表示差异，保持数字精度，拒绝实际金额变化；字符串、数组顺序及其他类型仍严格匹配。
- 修复证明的是服务端边界及持久化。浏览器对超大数值的输入、显示和编辑仍需在页面验收中验证。
