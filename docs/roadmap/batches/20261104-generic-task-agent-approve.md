## 工具与领域边界

输入为 `taskId`、当前任务 `version` 和可选 `comment`（最多 500 字符）。不接收租户、用户、角色、权限、确认布尔值、URL 或批量编号。类型化 Handler → `GenericApprovalTaskToolPort` → 本地 Adapter → 既有 `GenericApprovalTaskService.approve`，复用人工审批的锁定顺序、乐观锁、冻结流程、下一节点校验、事务审计和通知，不复制状态机，也不调用其他 Handler。

输出中的 `status=APPROVED`、`version` 均属于刚处理的任务节点，`applicationStatus=PENDING/APPROVED` 表示整单进度。双语结果分别说明流转到后续节点和最终通过，不能把单节点通过描述成整单已完成。成功后仅从结果中的有效任务编号进入固定通用任务详情；未成功或结果不确定不自动导航或重新执行。

通用详情窗口在真实详情读取完成且当前作用域仍有效时发布 `taskId`、`taskVersion`，关闭、切换、撤权、加载中或版本异常时清除。服务端待办页面上下文只接受已登记标量，页面上下文不构成写授权，模型必须将当前任务版本用于写命令，不能使用申请版本替代。

Port 只使用 Java 标量和记录，不携带 JSON、Map、框架 DTO、地址或凭据。未来远程 Adapter 可替换传输，但领域服务仍须校验可信调用坐标及实时权限。

## 安全和状态

- 固定 L2、SECONDARY、ASSIGNED_TO_SELF、SINGLE_WRITE、NEVER；一个计划最多一个写步骤。
- 要求 `approval:act`、独立 `agent:tool:approval.genericTask.approve`、待办页面权限；工作空间同时要求业务页面权限。
- 仅真实确认凭证允许入队，签发、入队和 Gateway 执行前重新解析权限；领域再次校验租户、受理人、非本人审批、任务状态/版本、申请/实例关系、冻结快照和当前流程顺序。
- 下一处理人必须有效、同租户、有审批权限且不是申请人；任何失败均不消费当前节点。
- 业务状态、任务、实例、快照游标、动作流水、通知和业务审计同一领域事务。前置网关审计失败拒绝调用；写后结果不确定保持人工核实状态，禁止自动重试。
- 新工具默认禁用，既有全局和租户写开关不变。只在自建隔离测试库显式启用；运行发布仍遵守人工发布门，不扩大永久禁止能力。
