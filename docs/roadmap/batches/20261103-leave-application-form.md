读取仍为既有审批上下文、请假详情和领域审批人候选接口。请求依赖实际 `route:leave-application` 与 `leave:create`；编辑草稿还核对真实编号、申请人、DRAFT 状态及 canEdit，其他申请人的审计可读记录不能成为可编辑表单。非法编号在读取前拒绝，不退化成新建。旧身份、权限版本、旧草稿以及 A→B→A 的迟到响应不能回填当前表单。

审批人选择复用 BusinessUserSelect，按当前租户的真实领域资格搜索，20 条一页，滚动继续加载，不再固定截取前 100 人。API 客户端增加可选 keyword/page/size 对象，保留旧关键字调用方式与默认参数，没有改变服务端 HTTP 合约。共享选择器可展示领域返回的当前选择标签，即使其不在本页；该标签只用于显示，不构成资格凭证。服务端在实际保存/提交时重新校验资格，提交沿用领域的当前有效审批链解析，不把客户端选人当成授权。

候选元数据按身份及查询作用域隔离，旧搜索结果不能覆盖较新返回的同一候选；workflow 预览使用当前选择，清空后不会继续显示原审批人。搜索失败真实提示，重新打开选择器可重试，不用员工全目录或本地角色推断补齐结果。

## 草稿、确认与提交

保存前同步加锁，再做现有必填校验；保存及待确认期间禁用表单与 Agent 编辑入口。日期、时段、原因和审批人使用 Ant Design 控件，补充过去日期与倒置半天范围校验。最终有效性仍由后端校验，前端不增加虚拟请假记录。

确认弹窗绑定当前表单作用域，展示实际假种、审批人编号、日期/时段和事由，提交使用该快照。人工流程仍为保存草稿后调用既有提交接口；每一步检查当前身份及作用域。保存成功而提交失败时保留服务端返回的新版本，不自动重试，下一次必须重新人工确认。新申请的部分保存失败路径定位已知草稿地址，重新读取服务端状态，避免刷新后丢失记录入口；读取不代表再次提交。

保存/提交回执核对本人、编号、假种、日期、时段、事由、目标状态与递增版本，才可报告成功或导航。服务端仍可按现有有效审批链解析最终审批人。撤权、切换身份、换草稿和卸载后，旧完成回调不能修改当前表单、跳页或显示旧提示。前端停止等待不会撤销已完成的领域事务。

Agent 页面处理器仅提供打开新表单、类型白名单填写和无提交按钮的预览。正式写入仍通过已存在的领域工具和 Tool Gateway，不增加提交 UI 指令、不开放公共 Handler、不改变工具发布开关或单写限制。
