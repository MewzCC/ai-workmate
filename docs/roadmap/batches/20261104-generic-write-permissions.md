# 通用申请写权限独立批次

承接 `c3ca5c29`。本批只修复人工通用申请写入口的权限边界，不包含尚未完成的顺序审批运行时、流程快照、通用待办页面或其他积压改动。

## 改动范围

页面可见权限不再等价于业务写权限。认证用户每次调用均从现有 UserAccessService 解析实时权限，同时校验 `route:approval-start` 与操作对应权限：

| 接口操作 | 业务权限 |
| --- | --- |
| 创建、编辑草稿 | `approval:create` |
| 提交已有草稿 | `approval:submit` |
| 直接创建并提交 | `approval:create` 和 `approval:submit` |
| 取消草稿 | `approval:cancel` |
| 撤回 | `approval:withdraw` |
| 催办 | `approval:remind` |
| 恢复草稿 | `approval:reopen` |

无权限在读取业务资源或修改数据之前返回现有国际化 `PERMISSION_DENIED`。详情和列表的编辑、取消、撤回、催办标志也同时检查当前页面与业务权限，撤权后不继续展示可执行能力。资源归属、租户、合法状态、乐观锁等原有检查继续保留。

不改变接口形状、不修改数据库或迁移、不开放任何 Agent 工具。已拥有页面访问权限但未获独立业务授权的用户将被拒绝写入；应由权限管理员按职责显式授权，不能回退为前端放行。

## 提交与回滚边界

仅暂存本批服务权限变化、对应测试与夹具、本文档。服务文件内其他正在开发的流程变化不进入本批。验证针对独立导出的暂存快照执行，避免其他未完成代码影响结论。没有数据库变更；回退本提交会重新暴露页面权限代替业务权限的问题，优先向前修复。

后续先收口通用申请快照与人工顺序审批，再单独接通受 Tool Gateway 保护的通用任务工具。现有页面交互、国际化与浏览器回归改动继续按各自业务边界分批整理，不能为了减少工作区文件数而合成一次大提交。每批完成开发后集中验证，通过即提交，再进入下一批。
