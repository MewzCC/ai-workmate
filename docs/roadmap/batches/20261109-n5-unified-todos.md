# N5 四类统一待办

基线 `1aa3edcb`，对应[业务缺口计划](../20261109-missing-business-capabilities.md) N5 / G05。

统一请假、通用审批、访客与用印任务的列表、分页、状态、计数及详情定位；驾驶舱的待办 / 逾期数量、待办摘要和受控导出复用同一有效资源关系。

## 范围与权限裁定

- 保留已有请假 / 通用审批的 `todo:read` 范围；访客和用印还须分别具备 `visitor:read:self`、`seal:read:self`。ALL 过滤无权业务，显式请求无权业务返回权限错误，摘要不泄露不可见任务。
- 读取资格与审批资格分开。审批权限撤回后，有业务读取权限的受理人可以只读历史 / 当前记录；所有写入继续由 Gateway 与领域服务实时拒绝。前端详情入口还校验对应页面权限。
- 本批同步驾驶舱的“待办”口径；本人申请、消息、申请趋势等非待办指标保留其已有定义，不声称本人申请页面已统一四种业务。
- 只投影有界任务摘要，不返回业务原始表单、电话、车牌、附件或对象路径。不同业务编号可以相同，任何详情都按固定业务类型分派。

## 接口与导航

- `GET /api/todos` 的 `businessType` 接受 `ALL`、`LEAVE_APPLICATION`、`GENERIC_APPROVAL`、`VISITOR_BOOKING`、`SEAL_USAGE`；保持最大每页 50 条、统一排序和分页。默认状态仍为 `PENDING`。
- `GET /api/todos/{taskId}/summary` 返回当前身份可见的固定业务类型和业务编号；原 `GET /api/todos/{taskId}` 仍只读取请假，不把其他类型错误解释成请假。
- 访客、用印详情分别进入 `/oa/visitor-booking?id=<业务编号>`、`/oa/seal-usage?id=<业务编号>`。统一待办先读取真实摘要和对应领域详情，核对坐标后导航。驾驶舱按代码内固定路由分派。
- 待办计数、逾期计数、列表、摘要和驾驶舱导出共享任务 / 实例 / 业务记录的有效关联。访客与用印额外核对申请人、当前受理人和资源绑定实例，并按任务 / 实例 / 业务状态组合过滤异常数据。
- 已通过任务在访客签到 / 到访 / 离场及用印 / 归还后保留审批历史。读取不代表获得办理资格；当前办理入口仍由领域详情与审批权限控制。
- 驾驶舱访客 / 用印预审入口明确禁用，避免借请假预审 Prompt 错读业务；办理入口进入真实领域页面。
- 驾驶舱概览、导出回调、指标设置回调增加身份 / 权限快照防护，迟到响应不能覆盖切号或撤权后的界面。
