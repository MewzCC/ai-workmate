# Agent 缺参追问闭环实施与验收

基线 `9eecfe7c`。已确认的问题是 Planner 将缺参追问产生的空步骤结果归为契约错误，前端只能显示失败。目标是侧边 AI 与 Workspace 都能追问、补充、重新规划，并在写入前再次确认；不新增工具或扩展写权限。

## 实现设计

- Planner 增加可选的 `clarification` 问句，长度最多 500 字符；只能与空步骤一起出现。普通空步骤、未知字段、混合追问与执行步骤继续拒绝。提示词版本更新，不修改既有工具合约。
- 追问保存为 `NEEDS_INPUT`，有 UUID、计划哈希及 15 分钟有效期，但没有待执行步骤。该状态允许取消或过期，禁止排队、执行或签发确认。
- 计划请求可携带 `clarificationTaskId`。服务端锁定原任务，校验认证用户、租户、原页面、会话、状态、有效期及最多三轮补充；只合并原用户请求和本次补充，UTF-8 总输入不得超过 4096 字节和运行配置输入上限中的较小值。
- 补充时生成全新计划与哈希，原追问转为取消，不复用旧步骤或凭证。创建、幂等、关闭原追问及新计划保持同一事务；失败回滚，重试同一幂等键返回原结果。并发补充不能消费同一追问两次。
- Workspace 保存用户原文和助手问句，刷新可恢复待补充状态；补充自动回到操作规划，仍可取消。侧窗切页后保留追问并回到原页面能力上下文规划，不借当前页面扩大工具范围。
- 共用前端状态判断与计划预览；追问卡片不显示执行/确认按钮。所有新增可见文案同步中英文。
- 新增时间戳迁移仅扩展任务状态约束；历史迁移不改。模型任务和业务写入继续经过原 Gateway 与实时领域校验。

15 分钟及最多三轮为本批实现选择，不是用户指定数值；其作用是给人工补充提供有限窗口，不提高模型执行预算、工具调用次数或单写上限。

## 串行步骤

1. Planner 追问合约及拒绝路径测试，先观察现有实现失败，再实现。
2. 任务状态、受控关联、幂等与并发、取消/过期、会话持久化和迁移。
3. 两个前端入口的补充与恢复，共享展示和按钮限制。
4. 真实 PostgreSQL/HTTP/Worker/Gateway 验证及真实模型多轮、浏览器回归。
5. 完整前后端门禁、运行更新和独立中文提交；未通过不混入其他功能。

## 验收门禁

- 正常追问零步骤、零 Handler、零业务变动；不能直接 execute 或 confirmation-token。
- 补充后重查实时权限、工具和页面策略；跨租户/用户/会话/页面、过期、取消、超轮及超长输入均拒绝。
- 同幂等重试、并发补充、断网恢复及重复确认不产生第二次执行。
- 正常聊天、原有非追问计划、SSE、身份切换、小窗持续性、输入清空及确认流程不回归。
- 实际迁移空库/旧库、Flyway validate 和真实重启；新增真实数据库用例不跳过。
- 侧窗和 Workspace 完成“请求缺参 → 可读问句 → 补充 → 新计划 → 人工确认 → 唯一真实结果”。

本批实现与集中验收已完成；历史失败记录保留用于追溯，最终结果见末节，不以设计清单代替证据。

## 部署与回滚

- 新迁移 `V202611161000` 只增加状态约束允许值，无新增工具、业务表或默认启用开关。先备份本地开发库，再由匹配版本后端执行 Flyway；部署需同步后端与 OA，避免旧端无法识别追问状态。
- 回滚前停止接收新计划，等待或由本人取消已有 `NEEDS_INPUT`；旧应用无法恢复这些问句。保留扩展后的约束及迁移历史，不删 history、不改脚本，不伪造写操作结果。必要时按备份恢复专属本地环境；生产发布不在本批授权范围。
