# N10 动态子表格验收记录

## 合约与实现

- 一张申请中的表格最多 20 行、10 列；列类型限定为文本、多行文本、数字、金额、日期、时间、单选及下拉选择。
- 列定义仅允许 `name/label/type/required/options/min`，禁止嵌套表格、脚本和动态表达式。单元格最多 500 字符，选项最多 10 个。仍受整张申请现有 JSON 容量限制。
- 前端设计器配置列、交互预览、申请行增删均使用 Ant Design；桌面和移动端共用 `ResponsiveTable`。草稿允许缺少必填单元格，提交时检查。
- 金额使用十进制字符串或服务端 BigDecimal；不通过浮点数重写已保存金额。时间固定 `HH:mm`。
- 选择/单选列必须配置至少一个合法选项；文本列仅接受字符串。HTTP 数值单元格无损规范化为普通十进制字符串，保留原请求对象不变；指数展开前先计算长度，超过 500 字符的值直接拒绝，避免巨型分配。
- 历史详情使用提交时冻结的列和行，列顺序不会随当前模板变更。敏感字段或敏感列的整张表格不进入 Agent 投影。
- Agent 参数使用 `fields[].rows[].cells[]`，单元格为 `name/value`，与标量 `value`、多值 `values` 三者互斥。行数据属于一次申请写入，不产生批量业务执行。
- 模板读取、本人详情及受理任务详情复用受限列/表格 Schema。详情文本提供行数和有限行摘要，结构化结果保留允许的完整表格。
- 新增 `V202611121700` 仅升级已知平台合约哈希，保留工具启用状态、权限及租户配置；不自动开放写工具。
- 裁定（Ruling）：新表格根字段名保留 `constructor/prototype/__proto__`，由设计器、控件能力判断及服务端列定义校验共同拒绝。原因是实际 Ant Design 表单无法可靠编辑对象保留根键；兼容代价是此类历史占位字段保持不可用提示，不能作为新表格定义发布。普通表格列可使用 `constructor` 作为纯数据键，读取时仅处理自有属性，不读取原型属性。

## 数据结构

申请表单保存为一组受约束的行对象，例如：

```json
{"items":[{"amount":"9007199254740993.01","note":"第一行"}]}
```

Agent 通过既有申请工具传递相同数据含义，不传原始 JSON 字符串或可执行表达式：

```json
{"name":"items","rows":[{"cells":[{"name":"amount","value":"9007199254740993.01"},{"name":"note","value":"第一行"}]}]}
```

历史字段返回可选 `table.columns` 和二维字符串 `table.rows`，单元格位置与冻结列顺序一致；非表格旧结果不要求这一属性。端口只依赖 Java，省略空列及空属性由工具协议层完成。

## 兼容与回滚

旧表单中的无列定义 `table` 占位仍可读取，申请界面显示不支持提示，不能凭空生成业务列。子表格不支持嵌套附件、人员或部门控件。

不修改任何已执行迁移；部署回滚须先关闭受影响表格写入入口及相关工具，保留已提交数据与快照。旧版不支持新表格编辑，工具合约不匹配时应保持不可用；如需降级合约，使用新的逆向迁移并复核权限状态，不能删除 Flyway 历史或伪装成旧哈希。本批不部署、不推送、不变更生产配置。
