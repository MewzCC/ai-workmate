# N9 申请附件与图片

本批基于 N8 提交 `bdc8121`。

申请人先保存草稿，再通过附件字段上传文件。上传接口实时检查申请创建权限、租户、申请归属、草稿状态及字段类型，与提交共用申请聚合锁。文件与图片大小沿用 `UploadProperties`。Tika 检查现有类型白名单，图片和业务附件校验独立于 OCR 及文本抽取偏好。

`V202611121500` 增加附件元数据表，并以联合外键绑定租户、申请及上传人。文件内容写入 MinIO，字段只保存最多 20 个受控附件编号。保存和提交检查附件对应的申请、租户、字段及类型。上传事务失败时通过事务完成回调清理对象。移除表单引用保留历史文件。

接口位于 `/api/approval-applications/{applicationId}/attachments`。上传使用 multipart POST，元数据使用 `GET /{attachmentId}`，内容使用 `GET /{attachmentId}/content`。历史详情可携带 `taskId`，服务端据此检查指定流程的参与权限和冻结数据引用。新草稿的附件由申请人及审计权限控制，旧流程处理人通过旧任务快照读取历史文件。响应只提供编号、展示名称、类型、大小与时间，下载采用附件响应及禁止缓存设置。

前端使用 Ant Design Upload、List 和 Image。上传期间锁住提交及 Agent 表单预览，账号、权限和表单切换时取消旧上传并丢弃迟到回执。历史申请和审批详情复用同一受保护附件列表。图片预览通过受认证内容接口生成临时 Blob URL，在关闭或作用域变化时释放。

Agent 可沿用既有草稿更新工具提交当前申请的有效附件引用。领域校验拒绝 URL、原始文件内容、其他申请附件及跨租户引用。文件二进制上传由用户操作完成。

测试使用隔离 PostgreSQL、原生 Redis 和独立 MinIO 进程。MinIO 测试凭据按运行随机生成，使用新数据目录和只监听回环的端口。运行时需要 `AGENT_TEST_MINIO_BINARY` 指向本机可执行文件。CI 使用 Go 1.24.6 构建固定 MinIO 源码提交 `07c3a429bfed433e49018cb0f78a52145d4bedeb` 并缓存测试二进制。依赖版本依据该源码的 [go.mod](https://raw.githubusercontent.com/minio/minio/07c3a429bfed433e49018cb0f78a52145d4bedeb/go.mod)。

真实存储用例包括上传绑定、审批人下载、图片 MIME 检查、大小及跨租户拒绝、审计失败后的数据库与对象回滚。前端定向用例覆盖有效回执、错误字段、草稿前置条件及迟到上传取消。
