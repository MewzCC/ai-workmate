# 通用申请人工顺序审批批次

承接 `15eac4a1`，处理 A25 的人工审批主链路。按已确认的分批交付方式，代码、接口、页面、迁移与相关验证一起独立提交；全页面 Agent 读写、流程高级模式仍属后续批次，不能用本批通过代替整个目标验收。

## 业务链路

通用申请提交时冻结表单数据、Schema、配置版本、规则及解析后的有序审批人列表，按流程实例保存到新 `approval_execution` 表。跳过 START/END，仅生成当前一个有效待办；当前节点通过后才创建下一个待办，最后节点通过或任意节点拒绝后结束实例并更新申请结果。角色、部门显式 SEQUENTIAL 组最多解析 50 人，资格过滤后才确定顺序；旧角色节点没有 mode 时保留单一代表的既有语义。

每次提交产生独立快照，拒绝后恢复草稿、编辑及重提不会改变原实例数据。审批人读取原实例字段投影，敏感字段隐藏，金额精度保留；后续表单、流程、规则修改不改变已提交申请。运行时仍检查下一审批人的当前有效状态、租户和审批权限。

所有审批写操作先锁定申请聚合，检查实时 `approval:act`、任务受理人、申请人不可自批、当前实例、状态及节点版本。申请、任务、游标、实例、动作记录、业务审计和通知处于同一事务；冲突不自动重试，不返回假成功。提交、催办与审批采用相容的锁顺序。

## 接口与页面

| 接口 | 含义及权限 |
| --- | --- |
| `GET /api/generic-approval-tasks` | 本人受理任务，`todo:read`；状态、日期与分页过滤，最多 50 条一页 |
| `GET /api/generic-approval-tasks/{id}?fieldPage=1` | 只读原实例详情；申请人、受理人、租户审计或有记录的抄送人；字段每页 50，最多 100 字段 |
| `POST /api/generic-approval-tasks/{id}/approve` | 明确确认当前节点；请求 `version` 和可选意见 |
| `POST /api/generic-approval-tasks/{id}/reject` | 明确退回当前节点；请求 `version` 和必填意见，最多 500 字 |

沿用 `Result<T>`、JWT Cookie、国际化错误，不接受调用方提供用户或租户身份。请假专属接口继续拒绝通用任务，两类业务不混用 DTO 或领域状态。

我的待办新增真实路由标签：`/oa/todo` 请假、`/oa/todo?kind=generic` 通用申请；`taskId` 查询参数恢复详情。使用 Ant Design、ResponsiveTable、共享移动断点、受保护详情预检、版本预检、明确确认、错误/重试/空态、分页与迟到回调隔离。成功流转下一节点时不宣称整个申请完成；未知写结果提示核对，不自动重复提交。

## 明确保留的后续工作

高级条件节点、抄送节点、延时、自我审批、多级主管、多人会签/或签、自动超时动作与命中后的规则执行尚未接通。未知节点在提交时拒绝；匹配需要执行动作的冻结规则会阻止通过，并允许合法的当前处理人明确退回，不静默忽略规则。Agent 通用待办、详情和审批工具及其导航、结果摘要由下一批接入 Tool Gateway，本批不调整工具放行开关。

驾驶舱的待办统计包含通用任务，但待办摘要查询目前仍只展示请假，后续统一通用任务摘要与导航。初轮类型隔离检查还暴露未知 HTTP 路径被全局异常处理映射为 500，需在后续异常映射批次修复；本批针对实际存在的请假读取、办理接口验证跨业务拒绝，不以错误路径充当类型隔离证据。
