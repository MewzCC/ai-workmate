# N4 用印受控审批与驳回

基线 `491a8012`，实施依据为[业务缺口计划](../20261109-missing-business-capabilities.md)的 N4 / G04。

复用 N3 的决策参数、回执、Handler 校验骨架、固定 Schema 和认证详情加载。用印保留独立 Port / Adapter / 领域方法、权限和状态约束；两个 L2 工具默认关闭，必须二次确认，不代替实际用印、归还或文件留档。

## 实现与接口

- 新增 `seal.approve` / `seal.reject`，各自要求独立工具权限、`approval:act` 和当前业务入口权限。输入仅为 `taskId`、任务 `version` 与审批意见 `comment`，驳回理由必填；身份与租户来自可信上下文。
- 共用 `WorkflowDecisionToolModels` 回执，明确区分 `resourceId` / `resourceVersion` 与 `taskId` / 任务 `version`；固定 `resourceType=SEAL_USAGE`，状态为 `APPROVED` / `REJECTED`，不返回文件路径或内部人员身份。
- 请求校验与任务资格判断从 N3 提取为共用实现；各自领域方法锁定各自业务记录，核对任务、实例、申请人与当前处理人的完整关联。用印成功审计与站内通知加入同一业务事务，通知失败时全部回滚。
- 受认证的 `/oa/seal-usage?id=<申请编号>` 可定位实际结果，复用 `useBusinessRecordDetail` 的身份 / 权限 scope 与迟到响应防护。审批入口不再将缺失任务版本替换为 0。
- 既有 `seal.query` 增加仅在当前任务可办理时出现的任务坐标。已成功的旧查询历史继续可读，但缺少坐标时明确要求重新查询；不修改历史快照，不补造编号。
