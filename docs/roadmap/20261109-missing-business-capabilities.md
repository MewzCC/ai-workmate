# 现有业务缺口与分批补齐计划

> 执行方式：按节点串行交付，使用既有工程规范与 executing-plans 流程；每个节点完成后独立中文提交，不混合业务模块。

**目标：**补齐当前页面、领域接口和受控 Agent 之间断开的业务链路，保留租户、实时权限、单写步骤和工具网关边界。

**架构：**复用领域 Service 与类型化 Port/Adapter。页面通过真实 API 读取和办理业务，Agent 通过 Tool Gateway 调用同一领域能力；只共享稳定的校验、分页和回执格式，不建设任意业务执行器。

**技术栈：**既有 Java 17 / Spring Boot / PostgreSQL / Flyway，React / Ant Design / ECharts，不为本轮新增大型依赖。

**需求依据：**用户 2026-11-09 明确要求重新盘点并补齐缺少的功能。本次允许重新规划新增能力；2026-11-04 的停止扩展记录作为历史保留，永久安全边界继续生效。实现依据为本文件的现状证据，以及 [Agent 安全边界](phase-2-agent-security-boundary.md)、[Tool Gateway](../architecture/agent-tool-gateway.md) 和 [工程规则](../rules/engineering-rules.md)。

## 全局约束

- 所有工具调用继续经过 Tool Gateway；Controller、Planner、Worker 不注入或直接调用 Handler。
- 单任务最多一个写步骤；审批类工具采用既有高风险确认策略，新工具默认关闭，运行发布单独验收。
- 输入中的租户、操作者、角色和权限不能由模型指定；领域 Service 再次核对认证坐标、资源、状态及版本。
- 人工和 Agent 业务写入共用领域事务，不能通过前端点击绕过业务校验。
- 新结构、权限种子与工具合约只新增时间戳 Flyway 迁移，不修改历史迁移。
- 新增可见文案同步 `zh-CN` / `en-US`；OA 控件使用 Ant Design，移动端沿用统一断点与 ResponsiveTable。
- 不增加权限修改、删除、批量审批、任意 URL / SQL / 代码执行、外部消息或后台自治能力。
- 每个节点只暂存对应文件，使用中文 Conventional Commit 主题与正文，禁止 `git add .`。

## 每批提交与验证门槛

先完成一个节点内的纵向实现，再集中跑相关定向验证与前后端检查，避免每改一个文件就重跑整套。节点未通过不进入下一节点。

标准业务批次执行 `fonted-oa` 的 `npm run lint`、`npm run test`、`npm run build`，以及 Java 17 下 `backend` 的 `mvn test`。数据库及工具合约变更额外执行真实 PostgreSQL 空库 / 旧库升级、Flyway validate、重复启动及相应 Worker / Gateway / HTTP 检查；不得静默跳过。

新 Agent 能力至少覆盖正常执行、权限不足、跨租户、错误资源、非法状态、缺少确认、实时撤权、版本冲突、重复提交、审计失败等场景。文档盘点批次只做源文件、引用路径和差异检查，不能记作功能交付。
